## Design questions to settle in brainstorming (bring these, do not re-derive them)

1. Storage: a `client_errors` MySQL table (DDL via `docker exec` or an n8n migration workflow) versus Slack-only. Recommend table plus a Slack line for new stack hashes only.
2. Payload: screen, message, stack hash (client-side, e.g. FNV of message + top frames), first 2 KB of stack, user agent, app version (`REACT_APP_...` build id or bundle hash), week display string, session id (per tab, `sessionStorage`), `kind` (onerror / unhandledrejection / boundary / api). Decide whether handled `ApiError`s (403/503/timeout) are reported too; recommend only `network`/`invalid_json`/`empty` codes, rate-limited.
3. Dedupe: client-side `sessionStorage` set keyed by stack hash, plus a per-session cap (e.g. 20) and a per-minute cap; server-side `INSERT IGNORE` on `(session_id, stack_hash)`.
4. Privacy: no item names or free text; strip URLs' query strings; the reporter must never throw (wrap everything, `keepalive: true`, and use `navigator.sendBeacon` only if the key can be sent, which it cannot as a header, so use `fetch` with `keepalive`).
5. n8n Error Workflow: an Error Trigger → HTTP Request to Slack; set `settings.errorWorkflow` on the 41 active workflows via REST PUT (the `apply` route in `n8n-wave.mjs` handles the settings filter). Note: after A, most data nodes have error outputs wired to `Respond 500`, so those failures are "handled" and will NOT fire the Error Trigger; decide whether the `Respond 500` branches should also post to Slack (or write a row) so real failures are not silent. Recommend a small shared "notify" sub-workflow called from the Respond 500 branches, throttled.
6. Test strategy: Jest tests for the reporter (mock `global.fetch` via `installMockFetch`, never `apiFetch`), a hermetic e2e that throws in-page and asserts one mocked POST (mock host `http://n8n.test/webhook/client_errors` in `e2e/support/mock-backend.js`; the catch-all aborts other hosts and the fixture teardown fails on unmocked requests, so the route must be registered), and a live check that posts one clearly marked `[TEST]` error and deletes the row. To test the Error Workflow, create a throwaway workflow with a Code node that throws, set its `errorWorkflow`, trigger it, confirm the Slack message, then delete it. Never make a real workflow fail on purpose.
